# MON-V1-002 implementation handoff

## Summary

Delivered Shipments continue automatic carrier checks while their follow-up date
is after today in New York. Staff can reopen completed records through a future
follow-up date. The frontend provides Monitor again on desktop, mobile and detail.

## Changes Made

- Separate known delivery from monitoring completion. Repeated delivered results
  retain active monitoring until the start of the follow-up date; null/today/past
  dates complete known deliveries. Undelivered tracking retains its lifecycle.
- Reconcile existing completed/future-date records on the worker's first scan;
  reconcile expiry on scans and outcome finalization. Preserve future manual and
  safeguard pauses, soft deletion, carrier availability, pacing and snapshots.
- Recheck the database-clock window at selection, enqueue/start and immediately
  before single/batch reads. An in-flight lookup may finish; a concurrent staff
  edit invalidates its old version. A session failure retains existing accounting.
- Reuse existing follow-up PATCH; edits reconcile immediately within its transaction.
  Exclude known deliveries from Upcoming and undelivered-only search independently
  of monitoring state. Generic change events keep list/detail/counts synchronized.
- No schema migration, new FK, environment change or dependency is needed. The
  user approved the existing library/built-in approach and this custom business
  policy after grilling. No reusable validator, scheduler or timezone replacement
  was introduced.

## Review Notes

The new policy uses the existing definition of known delivery: non-null
`currentTracking.deliveredOn`. Worker reconciliation updates stored state and
view membership on its next scan; a long scan can delay this display change.
Independent database-clock checks prevent new logical lookups after the deadline.
Already-started requests may finish, including adapter-internal retries.

No history is rewritten. Staff assignment attribution survives system reconciliation.
Manual resume still applies only to manual pauses; a future date alone does not
undo pauses. Existing disabled carriers can have active records but receive no calls.

Local manual testing uses an isolated fixture API on `http://localhost:3018` and
frontend on `http://localhost:5173`. Tracking worker is deliberately disabled in
this fixture; provider execution is covered by the integration tests.
